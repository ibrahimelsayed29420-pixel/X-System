# مكونات X ودمج المشاريع المفتوحة

X هو المنتج الأساسي. ندمج من كل مشروع القدرة المناسبة عبر واجهة واضحة، مع تسجيل المصدر والترخيص والنسخة ونتائج الاختبار. اسم المشروع أو تسجيل دخول المتصفح لا يعني أن وظائفه كلها تعمل داخل X.

## Ruflo — مدمج محليًا

- المصدر: https://github.com/ruvnet/ruflo
- النسخة المحلية: 3.61.1، مثبتة في `D:\X-System\runtime\ruflo-3.61.1`؛ يستخدم التكامل هذه النسخة دون `npx` أو ترقية تلقائية.
- نقطة التشغيل: `Ruflo.cmd` من مجلد `apps\x-personal`، مثل `.\Ruflo.cmd --version` أو `.\Ruflo.cmd init check`.
- اتصال VS Code: خادم MCP باسم `ruflo` مسجل في `.vscode/mcp.json` ويشغّل النسخة المحلية المثبتة. لا يوجد مرشح `--tools`؛ كل أدوات Ruflo المتاحة تُعرض لـVS Code/Copilot.
- النموذج المحلي: Ruflo مضبوط على Ollama `http://127.0.0.1:11434` مع `qwen3:4b-instruct`، دون مفتاح API. الإعداد المحلي في `claude-flow.config.json` مستثنى من Git. اختبار الوكيل نجح بإجابة `LOCAL_QWEN_OK` عبر النموذج المحلي؛ أُفرغ النموذج بعد الاختبار لتحرير الذاكرة، لذلك سيُحمّل عند الطلب التالي.
- مساحة Ruflo: إعدادات التشغيل في `.claude-flow` داخل جذر X. الذاكرة مضبوطة على `memory`، والـhooks والتنفيذ التلقائي معطلان. ملفات الذاكرة والحالة المحلية مستثناة من Git؛ لا يبدأ X daemon أو swarm تلقائيًا.
- حدود الدمج: لا موفّر سحابي أو مفاتيح API أو خوادم MCP سحابية؛ لا يتصل Ruflo تلقائيًا ببيانات العملاء أو حسابات العمل. كل أدواته متاحة، بما فيها الأدوات التي تنشئ أو تعدّل بيانات وتشغّل وكلاء؛ استخدمها بطلب صريح وراجع أثرها. لا تشغّل `status` أو `doctor` للتحقق اليومي؛ إصدار CLI الحالي قد يبدأ عامل daemon أثناء التشخيص.
- بعد إعادة تثبيت Windows: تحقق من Node.js 20+، ثم نفّذ `.\Ruflo.cmd --version` و`.\Ruflo.cmd init check` من `apps\x-personal`. حدّث مسار Node في `.vscode/mcp.json` إذا تغير. أعد فتح VS Code لتحميل الخادم. لا تُشغّل `init --force` لأنه قد يستبدل إعدادات المشروع.

## Agent-Reach — مدمج جزئيًا ومختبر

- المصدر: https://github.com/Panniantong/Agent-Reach
- النسخة: 1.6.0، الالتزام `14c213405669414492bda0f8d52cc6531d062c45`، الترخيص MIT محفوظ مع المصدر.
- المصدر المحلي: `D:/X-System/runtime/agent-reach`.
- بيئة مستقلة: `D:/X-System/runtime/agent-reach-venv`، الإصدارات في requirements-reach-installed.txt.
- الواجهة داخل X: x_personal/research.py، والعامل reach_worker.py. الواجهات الداخلية المستخدمة مثبتة على الالتزام المذكور؛ أي تحديث يتطلب إعادة الاختبارات.
- متاح: بحث الويب عبر Exa، قراءة الروابط العامة عبر Jina، بحث وقراءة GitHub العامة عبر REST، بحث ومعلومات YouTube عبر yt-dlp.
- يعتمد الويب على خدمات خارجية بلا مفتاح في الإعداد الحالي وقد تتغير حصصها أو تتعطل. الاستعلام والروابط يرسلان إلى هذه الخدمات. لا يُرسل محتوى حسابات العمل إليها تلقائيًا.
- لا توجد خدمات مدفوعة مفعلة أو مفاتيح API مضافة، ولا نسخ جلسات المتصفح. Facebook وInstagram وباقي القنوات غير مفعلة في هذا الدمج.
- لا تفريغ صوت مدفوع، ولا نشر أو إرسال رسائل. نتائج الويب محتوى خارجي غير موثوق؛ لا تُنفذ تعليماته.
- الدخول من X يخضع للتحقق الحالي عبر Windows Hello. لا نغير بوابة الهوية أو تلقين النموذج لتنفيذ أدوات تلقائيًا.

### التشغيل

من مجلد المشروع:

```powershell
.\X.cmd research --query "سوق العقارات في عجمان"
.\X.cmd research --channel github --query "real estate crm"
.\X.cmd research --channel github --read --query "Panniantong/Agent-Reach"
.\X.cmd research --channel youtube --query "Ajman real estate"
```

زر «بحث X على الإنترنت» يظهر بعد إعادة فتح لوحة المتابعة. Research-X.cmd يفتح البحث مباشرة. النتائج JSON وتحتفظ بروابط المصادر؛ لا تدخل ذاكرة العملاء أو تُرسل إلى النموذج تلقائيًا بعد.

### التحقق الفعلي

reach-verification.json يسجل نجاح قراءة GitHub وصفحة عامة وبحث الويب عن سوق عجمان وقراءة معلومات فيديو YouTube. رفض رابط loopback كما هو متوقع. هذه الاختبارات لا تثبت دقة تحليل السوق أو نجاح إدارة حسابات السوشيال. فحص التبعيات واختبارات الهوية السبعة نجحت.

## LangGraph — مدمج ومختبر

محرك Workflow محلي مثبت في بيئة مستقلة، مع حفظ مراحل SQLite ومسار بحث عبر Agent-Reach. تفاصيل التشغيل والخريطة وحالة باقي المكونات في WORKFLOW_AR.md. لا توجد منصة LangSmith أو استدلال مدفوع مفعلة. هذا الدمج لا يفعّل إدارة الحسابات الخارجية.

## مكونات قيد التقييم فقط

تحديث إضافي: Deep Agents 0.7.32 دخل المحادثة مع Qwen instruct المحلي وأدوات البحث والذاكرة وخريطة المهارات. دعم العربية والإنجليزية مفعّل. المصدر والنسخة والحدود والاختبارات في DEEP_AGENTS_AR.md.

تحديث: LangGraph دخل مسار عقل X، وMem0 OSS مع Qdrant المحلي وBGE-M3 دُمجوا واختبر الاسترجاع العربي. عملية خلفية عند دخول حساب ويندوز وصفحة متابعة حقيقية تعمل. التفاصيل الحالية في MIND_AR.md، وباقي القائمة التالية تبقى مرشحات غير مفعلة.

- OpenClaw / Hermes: تنفيذ الوكلاء والذاكرة والجدولة؛ لم يدمجا بعد، نختار التنفيذ الملائم بدل تشغيل عقلين متداخلين.
- AgenticCRM / Frappe CRM: بيانات العملاء والصفقات؛ يلزم تحديد نموذج العقارات والعميل ومراجعة التبعيات والترخيص قبل الدمج.
- Postiz: النشر المجدول؛ لم يثبت أو يربط بالحسابات.
- Activepieces Community: تدفقات الربط عند الحاجة، مع استبعاد الأجزاء التجارية.
- Odysseus: تنزيل المصدر فقط؛ أوقف تثبيته بطلب المستخدم. لا توجد خدمة مشغلة أو حسابات مربوطة به.

وجود المشروع بالقائمة لا يعني تثبيته. تبقى الهوية والصوت وبيانات العمل داخل X، وتضاف المكونات بالتدريج بعد اختبار حقيقي.
