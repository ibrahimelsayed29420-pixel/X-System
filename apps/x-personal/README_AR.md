# X — التعارف والتفاعل الشخصي مع إبراهيم

## تحديث الصوت وGitHub

الصوت الحالي: Piper 1.8.0 مع Kareem medium العربي الأردني، محلي بصيغة ONNX. عينة `piper-preview.wav` أُنتجت دون استخدام الميكروفون. هذه تجربة لصوت عصبي ولا تعني ضمان صوت بشري تمامًا أو لهجة مصرية. للرجوع لصوت Hoda غيّر `tts_backend` إلى `windows`. إعدادات ما قبل التغيير محفوظة في settings.before-piper.json.

محرك Piper من https://github.com/OHF-Voice/piper1-gpl بترخيص GPL-3.0. بطاقة الصوت في https://huggingface.co/rhasspy/piper-voices/raw/main/ar/ar_JO/kareem/medium/MODEL_CARD تحيل ترخيص بيانات التدريب إلى مصدره دون حسم واضح في البطاقة؛ لا يُعد تجهيز المعاينة اعتمادًا لحقوق استخدامه في إعلانات تجارية أو إعادة توزيعه.

حساب GitHub المتصل بـCodex تم التحقق منه باسم cloudstorageai. هذا ليس تسجيل دخول X المحلي. جُهّز GitHub CLI ARM64 في D:\X-System\runtime\github-cli. افتح Connect-GitHub.cmd وأكمل التفويض الرسمي في المتصفح، ثم ` .\X.cmd github-status ` للتحقق من اسم الحساب فقط. بيانات الاعتماد تُدار بواسطة GitHub CLI، ولا يقرأ X رموز الدخول أو يمررها للنموذج. لم يُنشأ مستودع ولم تُرفع بيانات أو ملفات شخصية.

أمر ` .\X.cmd updates ` يفحص الإصدارات العامة لمشاريع Piper وSherpa-ONNX وSilero VAD ويحفظ تقريرًا في D:\X-System\logs\x-release-review.json، دون تنزيل أو تشغيل كود تحديث. أُنشئت أيضًا متابعة يومية داخل Codex لهذه المشاريع عند الساعة 10 صباحًا بتوقيت الإمارات؛ تنبّه فقط للتغيير المفيد. المتابعة مرتبطة بتشغيل Codex وليست خدمة مستقلة في X.

التطوير الذاتي الكامل غير مفعّل: لا يستطيع النموذج الحالي تعديل نفسه أو توسيع صلاحياته. أي تطوير عملي يمر ببيئة اختبار، واختبارات، ونسخة رجوع، ثم اعتماد التغيير. الحسابات وملفات التعريف المحلية مستثناة عبر .gitignore، وهذه القاعدة لا تغني عن مراجعة الملفات قبل أي نشر.

## تحديث الاستماع: Sherpa-ONNX

أُضيف محرك `sherpa-onnx` 2.0.1 ونموذج Whisper base متعدد اللغات بصيغة INT8 ONNX. اللغة `ar` والمهمة نسخ الكلام، مع تنفيذ CPU بأربعة خيوط داخل بيئة Python x64 الموجودة تحت محاكاة Windows ARM. لا يوجد تفعيل لتسريع NPU في هذا الإعداد.

الإعداد `speech_backend` في settings.json يحدد المحرك؛ `sherpa-onnx` يستخدم النموذج في `D:\X-System\models\speech\sherpa-onnx-whisper-base`، و`vosk` يرجع للمحرك السابق المحفوظ. نتيجة الاختبار في `onnx-verification.json`. اختبار صوت Hoda المُولّد لا يقيس جودة لهجة إبراهيم الحقيقية.

التسجيل الحالي: بعد التحقق اضغط Enter للبداية، ثم Enter للنهاية. لم يعد الإعداد القديم listen_seconds مستخدمًا. في محرك ONNX حد وقائي دقيقتان للطلب الواحد، مع رفض الصوت المتقطع. الاستماع في الذاكرة دون حفظ تسجيلات. لم يُضف إنهاء تلقائي بالسكوت أو كلمة تنبيه أو تدريب شخصي بعد.

للتجربة: ` .\X.cmd listen `، وبعد مراجعة النص: ` .\X.cmd chat `.

المصدر: [مثال Whisper الرسمي لـSherpa-ONNX](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/offline-whisper-decode-files.py).

نسخة أولية محلية في `D:\X-System\apps\x-personal`. لا تعدل بيانات المكتب ولا تبدأ تجربة عقار. هذه وحدة مستقلة عن الخطوة 3 المتوقفة.

## الموجود فعليًا

- Python المستخدم الرئيسي: 3.15.2 ARM64، ومكتبة ollama 0.6.3 موجودة.
- نموذج `llama3.2:latest` موجود على خدمة Ollama المحلية، واختبار طلب نصي نجح.
- القيمة الفعلية لـ`OLLAMA_MODELS` هي `D:\X-System\models\ollama`، وليست المجلد الأب `models`. لم نغيّرها أو ننقل النماذج.
- صوت Windows محلي عربي مصري: Microsoft Hoda. توليد WAV عربي نجح في الذاكرة دون تشغيل السماعات.
- Windows Hello أبلغ `available`، وتنشيط واجهة الربط الخاصة بتطبيقات سطح المكتب نجح. التحقق الحقيقي ببصمتك أو PIN لم يُجرَ نيابة عنك.
- استُخدمت بيئة منفصلة `D:\X-System\runtime\x-personal-venv` تعتمد Python 3.12 x64 المرفق مع Codex. حزمة Vosk المتاحة لـWindows هنا x64، ولذلك يعمل الصوت تحت محاكاة Windows على ARM. لم تُغيّر نسخة Python ARM64 الرئيسية.
- حُددت أجهزة إدخال الصوت دون فتح تسجيل. فتح الميكروفون لا يتم إلا بأمر `listen` أو `chat` وبعد التحقق.
- اكتمل تنزيل النموذج العربي إلى D وفحص CRC للأرشيف. نتيجة فحص التشغيل التفصيلية في `verification.json`.

## التجربة بالترتيب

للتشغيل بالنقر: افتح `Enroll-X.cmd` أول مرة لربط حسابك، ثم `Talk-X.cmd` للكلام مع X. لا يبدأ التسجيل قبل إكمال التحقق والضغط على Enter.

افتح الطرفية في هذا المجلد. لا تحتاج تشغيلها كمسؤول.

```powershell
.\X.cmd doctor
.\X.cmd enroll
.\X.cmd speak
.\X.cmd chat --text
.\X.cmd listen
.\X.cmd chat
.\X.cmd inventory
```

1. `doctor`: يفحص توفر Hello والصوت العربي وOllama ونموذج الاستماع وربط الحساب. لا يفتح الميكروفون.
2. `enroll`: يعرض اسم حساب Windows الحالي، ويطلب كتابة **إبراهيم**، ثم يفتح نافذة أمان Windows. لا يحفظ الربط إلا عند نجاح التحقق. الربط لا يُستبدل تلقائيًا إذا كان موجودًا.
3. `speak`: يتحقق من الحساب ثم ينطق جملة عربية ثابتة.
4. `chat --text`: تدخل طلبًا بالكتابة، تؤكد هويتك، ثم يجيب النموذج المحلي ويقرأ الرد بصوت عربي.
5. `listen`: يتحقق من الهوية، ثم يستمع ثماني ثوانٍ افتراضيًا ويعرض النص فقط. يحتاج نموذج Vosk المحلي.
6. `chat`: ينتظر Enter، يتحقق من الهوية، يستمع، ثم يعرض ما سمعه. لا يرسل النص للنموذج إلا بعد كتابة **نعم** وتحقق جديد. لا ينفذ أي أوامر نظام.
7. `inventory`: بعد التحقق، يعرض معلومات النظام والمساحة ومعرّف الحساب الحالي. لا يحفظ تقريرًا تلقائيًا ولا يرسله للنموذج.

للخروج أثناء الاستماع اضغط Ctrl+C؛ يغلق مجرى الصوت. عند فشل Hello أو إلغائه يتوقف التفاعل ولا يوجد تجاوز تلقائي.

## نموذج الاستماع

النموذج المختار هو `vosk-model-ar-mgb2-0.4` بترخيص Apache-2.0 من Alpha Cephei، حجمه المنشور نحو 318 MB. مكانه منفصل عن نماذج Ollama:

`D:\X-System\models\speech\vosk-model-ar-mgb2-0.4`

إن قال `doctor` إن النموذج غير موجود، يمكن استكماله عبر:

```powershell
& 'D:\X-System\runtime\x-personal-venv\Scripts\python.exe' .\setup_speech_model.py
```

التنزيل من المصدر الرسمي، مع فحص CRC للأرشيف ومنع الخروج بمساراته خارج مجلد الاستخراج. يُسجل SHA-256 محليًا للمراجعة؛ ليس توقيعًا موثوقًا من الناشر. دقة النموذج مع اللهجة المصرية يجب قياسها بصوت إبراهيم؛ لا نفترض دقة كل جملة أو ضوضاء.

## ماذا يعني التحقق من الهوية؟

الاسم «إبراهيم» اسم تختاره أنت. Windows Hello يثبت الموافقة باستخدام وسيلة أمان الحساب المسجل؛ قد يعرض PIN أو بصمة أو وسيلة أخرى حسب الجهاز والإعدادات. لا يزوّد البرنامج بقالب البصمة أو صورة الوجه، ولا يثبت اسمك القانوني. لا توجد مصادقة مستقلة بكاميرا عادية.

هذه بوابة تفاعل داخل نموذج أولي، وليست خزنة أسرار أو حاجزًا ضد برنامج يعمل بصلاحيات حسابك ويعدل ملفات Python أو الإعدادات. لا تستخدمها وحدها لحماية معاملات مالية أو إرسال أو نشر. لا يوجد فتح حسابات خدمات تلقائيًا.

## حدود البيانات والاتصال

- مجلد `D:\الهوية - جهاز جديد` للقراءة فقط وفق طلبك؛ هذه الوحدة تفحص وجود المجلد فقط، ولا تقرأ محتواه أو تفهرسه أو تكتب فيه. هذا التزام في الكود وليس تعديلًا لصلاحيات NTFS للمجلد.
- لا قراءة لكلمات المرور أو Credential Manager أو الكوكيز أو حسابات المتصفحات أو الرموز السرية. الاستكشاف يقتصر على حساب Windows الحالي، وليس قائمة حسابات Google وMicrosoft والخدمات.
- لا تفعيل كاميرا، ولا تسجيل خلفي، ولا ملفات صوت من الميكروفون محفوظة، ولا سجل محادثة دائم.
- الصوت يُعالج محليًا، والنص يذهب فقط إلى `127.0.0.1:11434`. عميل النموذج يرفض إعادة التوجيه ولا يستخدم proxy، ولا يمرر أدوات تنفيذ إلى النموذج.
- نموذج `llama3.2` نصي؛ مكتبات الصوت منفصلة عنه. جودة العربية تحتاج تجربة فعلية.
- مساعد PowerShell للنطق يُشغّل بسياسة تجاوز تخص العملية فقط؛ لا يُغيّر سياسة Windows الدائمة.

## توجيه المهام والعقل الموحد

يستخدم X `x-ibrahim:latest` للمحادثة القصيرة، ويوجه البحث والخطط والتحليل إلى `x-qwen-agent:latest`. طلبات العقارات تستخدم تعليمات تخصصية لعجمان والشارقة لتنظيم عروض البيع والإيجار والأراضي والأوف بلان. قالب الإعلان لا يضيف سعرًا أو مساحة أو موقعًا تفصيليًا أو توافرًا لم يذكره المستخدم، ولا ينشر. هذا توجيه بين النماذج والمهارات المحلية، وليس تدريبًا أو تنزيلًا تلقائيًا.

## واجهة المحادثة المباشرة

افتح `Chat-X.cmd` أو `Brain-X.cmd`. يبدأ عقل X المحلي ويفتح لوحة المحادثة في المتصفح على `127.0.0.1`. اكتب رسالتك واضغط **إرسال** لعرض الرد. للصوت اضغط **تحدث** واسمح للميكروفون في المتصفح؛ أوقف التسجيل بعد كلامك، ثم راجع النص المفرغ محليًا وعدّله واضغط **إرسال** بنفسك. الحد دقيقتان، ولا يبدأ التسجيل إلا بضغطك، ولا يُرسل النص للعقل قبل تأكيد الإرسال. إذا كان التحقق مفعّلًا، يطلب Windows Hello قبل معالجة الصوت أو الطلب. تظل القناة محلية؛ لا Telegram أو WhatsApp مفعّل.

تم جلب MuseBot وHermes Agent إلى `D:\X-System\runtime` للمراجعة فقط. لم تُشغّل خدماتهما ولم تُثبت تبعياتهما. MuseBot يحتاج قناة ورسائل اعتماد لإرسال خارجي، وHermes يحتوي تشغيل أدوات أوسع من حدود X؛ لذلك تبقى القنوات والتنفيذ الآلي مغلقة. التفاصيل في `DEEP_AGENTS_AR.md`.

## ما تم اختباره وما يحتاجك

اختبارات الحدود السبعة تشمل رفض الحساب المختلف، ورفض التسجيل الملغى، وعدم فتح المستمع أو استدعاء النموذج عند رفض الهوية، ومنع مسارات أرشيف غير آمنة. فحص Hello وتوليد Hoda وطلب Ollama اختبارات فعلية، وليست نتائج محاكاة.

الخطوات البشرية الباقية: تسجيل ربط الحساب، إكمال Hello الفعلي، سماع الصوت، ونطق جملة لقياس دقة الميكروفون والتعرف. لا يُعتبر نجاح فحص توفر Hello نجاحًا للتحقق الحقيقي.

إعادة اختبارات الحدود:

```powershell
& 'D:\X-System\runtime\x-personal-venv\Scripts\python.exe' -m unittest discover -s tests -v
```
