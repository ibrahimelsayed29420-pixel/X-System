# X — مساحة عمل إبراهيم

الحالة: تجهيز ملفات وخطة استعادة فقط. ليس نظام أتمتة عاملًا بعد.

تحديث الجهاز في 29 أكتوبر: طُبقت خمسة متغيرات مستخدم دائمة لتوجيه كاش pip/npm/uv وبيانات Hugging Face ونماذج Ollama إلى D، وتحقق حفظها بقراءة مستقلة. تسري على البرامج التي تبدأ بعد التغيير؛ لا تغير البرامج المفتوحة تلقائيًا. Apply-Storage-Settings.ps1 يعيد تطبيقها بعد Reset، وRestore-Previous-Storage-Settings.ps1 يرجع القيم السابقة. لم تُنقل مجلدات النظام أو TEMP أو AppData بالكامل.

نُظفت جذور كاش pip وnpm وuv المحددة. ارتفع المتاح على C من نحو 19.16 إلى 25.09 GiB أثناء التنفيذ؛ تُركت ملفات npm المقفولة. هذه أرقام مشاهدة تتأثر بالنشاط المتزامن؛ التقرير cleanup-result.json. لم تُحذف مستندات أو برامج أو قواعد عمل.

أُنجز كذلك إنقاذ ملفات OneDrive الـ577 التي كانت معلقة والتحقق من محتواها، دون حذفها من الأصل أو السحابة. النسخة ليست صورة Windows كاملة؛ تسجيل الدخول ومفتاح الاسترداد يتطلبان تحقق صاحب الحساب قبل الفورمات.

## الهدف

مساعد يومي لإبراهيم السيد، مدير مبيعات On Time Real Estate LLC في عجمان والشارقة. يستوعب بيانات العقارات غير المنظمة (إيجار، بيع، أراضي، أوف بلان)، ويقترح تنظيمها وصياغة عروضها ومحتواها. يربط فهم النموذج بقواعد تحقق واضحة للحسابات والصلاحيات والخصوصية. هذا هو المقصود بالتصميم العصبي الرمزي؛ ليس مجرد تثبيت برنامج واحد.

## توزيع المساحة

- C: Windows، التعريفات، البرامج الأساسية والملفات التي تتطلب مسارات النظام. الهدف التشغيلي الاحتفاظ بنحو 50–60 GB فارغة قدر الإمكان؛ هذه سياسة وليست مساحة مضمونة بعد التثبيت.
- D:\X-System: المشروع والمحتوى والذاكرة وقواعد العمل والنماذج والكاش المحدد للأدوات.
- D:\X-Recovery: نسخة الإنقاذ السابقة للفورمات؛ تحتوي إعدادات حساسة، لا تُرفع إلى GitHub أو خدمات النشر.
- D:\الهوية وD:\الهوية - جهاز جديد: المشروع الحالي ونسخة المكتب؛ لا نقل أو استبدال لبيانات instance.
- لا تغيير لأحجام الأقسام. C وD على القرص نفسه، لذلك نسخة خارجية مستقلة لازمة للحماية من عطل القرص أو مسحه كاملًا.

نبدأ بسقف إرشادي 20 GB للنماذج و10 GB للكاش؛ هذه حدود تخطيطية وليست حصصًا مفروضة برمجيًا. لا تنزيل تلقائي لنماذج كثيرة أو تكرارها في أدوات متعددة. نحفظ الصور الأصلية مرة واحدة، ونربط بها نسخ المعالجة. لا حذف تلقائي للأصول أو نسخ المكتب. تفحص المساحة قبل تنزيل أي حزمة كبيرة.

## التثبيت بعد Windows

الجهاز: Microsoft Surface Laptop 13in 1st Ed with Snapdragon، ARM64، RAM قرابة 16 GB.

1. استعادة Windows والتعريفات من Microsoft وتحديث النظام، دون مسح D. التحقق من دخول الحساب ومفتاح الاسترداد أولًا.
2. تثبيت Codex وتسجيل الدخول. إعادة المهارات والإعدادات بشكل انتقائي بعد مراجعة المسارات؛ لا إعادة نسخ قواعد التطبيق على نسخة مختلفة وهي تعمل.
3. Git الحالي محفوظ في D:\Git؛ يتحقق تشغيله بعد الفورمات. Node.js وPython بإصدارات متوافقة ARM64، وتثبيت الأدوات الضرورية فقط. RTK محفوظ ضمن نسخة الإنقاذ. Ruflo 3.61.1 مثبت محليًا ومتاح بكل أدواته عبر MCP في VS Code، واختُبر وكيله بنموذج Qwen محلي عبر Ollama؛ تفاصيل إعادة الفحص في `apps\x-personal\INTEGRATIONS_AR.md`.
4. تجهيز استخراج نصوص PDF والجداول ثم OCR عربي عند الحاجة، وFFmpeg للصور والفيديو بعد التحقق من البناء المتوافق.
5. محرك نموذج محلي صغير اختياري بعد قياس الأداء؛ لا افتراض تشغيل GPU/NPU أو صلاحية حزمة x64 على ARM64. Ollama أحد المرشحين وليس مثبتًا أو مختبرًا ضمن هذه المرحلة. لا Docker/WSL أو أطر متعددة قبل إثبات الحاجة.
6. اختبار استيراد عقارات تجريبية: حفظ المصدر، استخراج حقول مع درجات ثقة، كشف التكرار، مراجعة إنسانية قبل اعتماد السجل، وحسابات بقواعد حتمية.
7. المحتوى: مسودة إعلان وصور وفيديو قصير، ثم مراجعة الحقائق والحقوق قبل النشر.
8. WhatsApp: إعداد رسمي وقراءة مصرح بها، ثم مسودات ردود قبل تفعيل أي إرسال تلقائي بموافقة منفصلة. لا استخدام لجلسات مسروقة أو أتمتة غير رسمية كبديل للربط المعتمد.
9. متابعة GitHub والمنافسين: مصادر عامة وقائمة مشاريع محددة وتقارير تغييرات؛ لا تثبيت أو ترقية تلقائية من مستودعات غير مراجعة.
